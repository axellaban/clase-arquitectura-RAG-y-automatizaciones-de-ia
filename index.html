Conceptos Base

¿Qué es exactamente RAG?

Definición de Negocio

Es la tecnología que permite que tu IA deje de responder basándose solo en lo que "aprendió" en internet y pase a responder desde el conocimiento real de tu empresa.

  • Reduce alucinaciones: solo habla de lo que sabe.
  • Construye Confianza: cita fuentes exactas.
  • Cero Reentrenamiento: actualizás el PDF y la IA ya lo sabe.

Definición Técnica

Retrieval-Augmented Generation: Una arquitectura que divide el proceso en dos etapas: primero recupera documentos relevantes y luego los inyecta en el prompt para generar la respuesta.

Ya tenés un agente con rol y personalidad. El problema aparece cuando tiene que responder algo específico de tu negocio.

de los equipos que usaron IA sin RAG en producción reportaron al menos un error crítico de datos en el primer mes.

El problema: La IA generativa sin contexto propio inventa — con el mismo tono seguro y convincente que cuando tiene razón. En un proceso real, eso no es un bug menor: es un problema de confianza que se paga caro.

Fuentes: (88%) Gartner AI in Production Survey 2024 — "AI Hallucination Incidents in Enterprise Deployments"; (3×) Databricks "Long Context RAG Performance of LLMs" — análisis de tiempo de corrección vs. prevención; ($0) Google AI Developer Blog, nov. 2025 — Google File Search API pricing.

Sin RAG vs. Con RAG

❌ Agente SIN RAG

  • Responde desde entrenamiento obsoleto.
  • Inventa políticas y datos con total seguridad.
  • No puede citar fuentes — no tiene de dónde.
  • Destruye confianza en el primer error real.

✅ Agente CON RAG

  • Consulta tus documentos reales antes de responder.
  • Dice "no tengo esa info" cuando no la hay.
  • Cita el documento y la sección exacta.
  • Actualizable sin reentrenar el modelo.
Objetivo de la clase: Que tu agente deje de responder con información genérica y empiece a responder desde el conocimiento real de tu negocio — y sepa cuándo y cómo derivar a un humano.

De Copilot a Autopilot

La decisión más importante antes de escribir el primer nodo.

🧑‍✈️ Copilot — Empezamos acá siempre

  • El agente propone — el humano aprueba y ejecuta.
  • Draft listo → humano revisa → humano envía.
  • Riesgo bajo. Ideal para procesos nuevos o críticos.
  • Genera los datos que necesitamos para confiar en el sistema.

🤖 Autopilot — Llegamos acá con datos

  • El agente propone Y ejecuta solo.
  • Nadie revisa — el sistema actúa autónomamente.
  • Solo para procesos ya validados con métricas reales.
  • Requiere >95% de precisión sostenida en ese proceso.
Regla del programa: Empezamos en Copilot. Pasamos a Autopilot cuando los datos muestran >95% de decisiones correctas para ese proceso específico. No antes. — Los procesos con Agentic RAG bien implementado muestran -78% de errores operativos respecto a flujos sin RAG.

El Ciclo de 6 Pasos RAG

Lo que pasa entre que el usuario pregunta y el agente responde con información real.

1. Pregunta
del usuario
→
2. Embedding
(vector numérico)
→
3. Búsqueda
semántica
4. Recuperación
top 3-5 chunks
→
5. Generación
(prompt + contexto)
→
6. Respuesta
fundamentada
Dos momentos clave. Preparación (pasa una sola vez): tus docs se dividen en fragmentos → cada fragmento se convierte en un número que representa su significado → esos números se guardan en la base vectorial. Consulta (pasa en cada interacción): la pregunta del usuario también se convierte en número → el sistema busca los fragmentos más "cercanos" semánticamente → los inyecta en el prompt → el LLM responde con ese contexto como base. Si en el paso 4 no encuentra nada relevante → el agente responde "no tengo esa info". Eso es RAG bien implementado.

BLOQUE 3 · FAST WINS · 15 MIN

NotebookLM: tu primer RAG en 15 minutos

Sin código. Sin infraestructura vectorial. Para validar que tu base de conocimiento funciona antes de invertir en arquitectura.

1
Crear el notebook → notebooklm.google.com → New notebook → nombre de tu caso de uso.
2
Cargar documentos → Add source: PDFs, Google Docs, links de Drive, URLs, texto pegado directo.
3
Esperar el procesamiento → 2-3 min para 10 docs · 5-10 min para 50 docs. Vectorización automática.
4
Testear con preguntas reales → Las mismas que te hacen tus clientes o tu equipo hoy.
5
Revisar las citas → Cada respuesta cita el doc y sección exacta. Si cita mal → ese doc necesita mejor estructura.
6
Compartir con tu equipo → Share → acceso directo. Ya tienen un asistente RAG funcionando hoy.

NotebookLM: cuándo usarlo y cuándo dar el salto a n8n

✅ Lo que hace bien

  • Cita fuentes con precisión — doc + sección exacta.
  • Hasta 50 documentos por notebook.
  • Genera FAQs, resúmenes y guías automáticamente.
  • Audio overview: podcast generado desde tus docs.
  • Cero código, cero infra, listo en 15 minutos.

⚠️ Cuándo necesitás n8n

  • La versión consumer no tiene API pública — no conecta con n8n, WhatsApp ni Telegram.
  • Solo integra con ecosistema Google (Drive, Docs, Workspace).
  • Necesitás lógica HITL o condiciones de escalada.
  • Necesitás registrar métricas y conversaciones.
  • Necesitás personalización de flujo o integraciones custom.
Victoria rápida real: Cargá tu manual de producto o política de atención en NotebookLM y compartí el link con tu equipo hoy. En 15 min tienen un asistente que cita el documento exacto.

⚠️ Regla para que funcione bien: Cada doc responde UNA pregunta concreta. Los títulos son preguntas reales del cliente, no categorías internas. Las respuestas incluyen números y condiciones específicas — no generalidades. Garbage in, garbage out.

Contexto masivo: dos plataformas clave

Caso 1: NotebookLM nativo

Uso directo desde su plataforma web. Hoy es la herramienta gratuita más poderosa para manejar grandes contextos de múltiples fuentes simultáneamente.

  • Poder Multimodal: Analiza PDFs, YouTube, audios y webs juntos
  • Audio Overview: Genera podcasts sobre tus propios documentos
  • Sin código, cero infra, ideal para investigar y crear
  • No tiene API pública para conectar con WhatsApp o Telegram

Caso 2: Google Gemini + NotebookLM

Desde la app de Gemini podés conectar con un notebook de NotebookLM como fuente de grounding (respuestas ancladas).

  • Modo conversacional directo sobre tus documentos
  • Incorpora visualización de citas exactas en las respuestas
  • Ventana de 1M tokens — hasta 700 páginas de contexto
  • No escalable mediante integraciones automatizadas o n8n
Regla práctica: Estas herramientas nativas son imbatibles para explorar bases documentales grandes porque absorben el costo del contexto masivo y la complejidad del chunking. El verdadero desafío surge cuando querés llevar este nivel de contexto e interacción hacia un agente automatizado en n8n orientado a cliente.

El criterio de decisión RAG: 3 preguntas

La decisión no es técnica primero — es de negocio. Respondé estas tres preguntas y la respuesta es clara.

① ¿Cuántos docs y cuánto cambian?

  • Pocos, estáticos: System Prompt (hack)
  • Muchos, estáticos: Google File Search
  • Crecen constantemente: Supabase / Pinecone

② ¿Necesitás datos dinámicos?

  • Stock, pedidos, CRM en tiempo real
  • Si sí → nodo adicional en n8n que consulta la API
  • El RAG solo maneja documentos, no datos en vivo

③ ¿Cuál es el volumen de consultas?

  • Bajo-medio: cualquier opción
  • Alto (miles/día): Pinecone o Supabase con HNSW
  • Muy alto B2C: Pinecone serverless
Regla práctica: Empezá con System Prompt o Google File Search — hoy, sin infra. Cuando el sistema crezca y los límites aparezcan, migrás. La migración toma horas, no semanas.

Arquitectura del Flujo RAG

El flujo genérico de RAG con File Search + datos dinámicos. Aplicable a cualquier caso de uso.

1
Trigger — Webhook recibe mensaje → normaliza: message_text, sender_id, chat_id.
2
Búsqueda RAG (Google File Search) — n8n consulta la base de conocimiento semántica con la pregunta del usuario. Si no encuentra → el agente responde "no tengo esa info" y ofrece alternativas.
3
Datos dinámicos (Google Sheets) — Si el caso necesita datos en tiempo real (calendario, scores, stock), n8n consulta el Sheet con los parámetros extraídos.
4
Generación — Agente genera respuesta con contexto RAG + datos dinámicos + historial de conversación. Máx. 4-5 líneas.
5
Respuesta — n8n envía la respuesta. Sin escalada humana — el agente resuelve autónomamente.
File Search = RAG sin infra: El conocimiento está en documentos indexados por Google File Search, no en el system prompt. Es plug-and-play: subís los PDFs, File Search los indexa automáticamente, y el agente recupera los chunks relevantes. Zero config.
Demo 2 · Saga Hormozi

RAG Avanzado: Saga de libros Alex Hormozi

Asistente en Telegram que responde preguntas sobre los 3 libros de Hormozi ($100M Offers, $100M Leads, $100M Legacy) — con RAG usando Pinecone y reranking explícito.

Stack de esta demo

n8n + Telegram + Pinecone (vector store) + OpenAI (embeddings) + Re-ranker

Misma arquitectura para docs técnicos, bases de conocimiento enterprise, o cualquier caso donde necesitás afinar el retrieval.

Arquitectura Pinecone + Reranking

El flujo RAG con control total. Cada paso es visible y ajustable.

1
Trigger — Webhook recibe mensaje de Telegram → normaliza: message_text, sender_id, chat_id.
2
Embed Query — OpenAI convierte la pregunta del usuario en un vector (1536 dimensiones). Este vector es la representación semántica de la pregunta.
3
Vector Search (Pinecone) — Busca los top 10-20 chunks más similares en el vector store usando cosine similarity. Cada chunk tiene su score de 0 a 1.
4
Reranking — El nodo Re-ranker reordena los chunks usando un modelo especializado. Los top 3-5 chunks con mayor score pasan al agente.
5
Generación — Agente genera respuesta con el contexto rerankeado + historial de conversación. Máx. 4-5 líneas.
6
Respuesta — n8n envía la respuesta por Telegram.
Diferencia clave con File Search: File Search es plug-and-play pero caja negra. Pinecone te da control: ves los scores, podés filtrar por metadata (ej: solo capítulo 3), ajustar cuántos chunks recuperar, y el reranker mejora la precisión un 20-30% vs. similarity pura.

Guardrails — Los límites del agente

Aplican a las tres demos. Podemos implementarlas como reglas explícitas en el system prompt, o utilizar el nuevo nodo de Guardrails nativo de n8n para validar la respuesta antes de que salga al usuario.

Guardrails de datos

  • Stock/info: No confirmar sin consultar la fuente real
  • Precios: No inventar descuentos ni condiciones fuera del prompt
  • Links/alias: No generar URLs ni datos de contacto inventados
  • Loop: Máx. 3 turnos sin resolución → escalar o redirigir

Guardrails de marca

  • Tono: El agente habla como la marca — definido en el prompt
  • Longitud: Máx. 3-4 líneas — chats no son emails
  • Temas off-limit: Competidores, política → redirigir siempre
  • Fuera de scope: "No tengo esa info" → ofrecer alternativa

# BASE DE CONOCIMIENTO

{{ $json.rag_context }}

Datos dinámicos en tiempo real (stock, precios, calendario):
{{ $json.dynamic_data }}

# HISTORIAL DE LA CONVERSACIÓN
{{ $json.conversation_history }}

# MENSAJE ACTUAL DEL USUARIO
{{ $json.message_text }}

# REGLAS INVIOLABLES
1. **Solo usás info de la base de conocimiento o datos dinámicos.**
   - Si no está → "No tengo esa información disponible" + sugerí alternativa.
   - Si el contexto RAG está vacío o irrelevante → admitilo.

2. **NUNCA inventés:**
   - Stock, precios, plazos, políticas, datos técnicos.
   - Si el usuario pregunta algo fuera de scope → "Eso no lo manejo, 
     pero puedo ayudarte con [X, Y, Z]."

3. **Estructura de respuesta:**
   - Máximo 3-4 líneas (excepto si listás productos/opciones).
   - Si diste info → cerrá con próximo paso o pregunta concreta.
   - Si derivaste → explicá por qué.

4. **Guardrails de marca:**
   - No hables de competidores.
   - No des opiniones políticas ni temas sensibles.
   - [AGREGAR REGLAS ESPECÍFICAS DEL NEGOCIO]

5. **Manejo de casos edge:**
   - Info contradictoria entre RAG y datos dinámicos → priorizá datos dinámicos.
   - Usuario frustrado después de 3 intercambios sin resolver → 
     [DERIVAR A HUMANO / ESCALAR].
